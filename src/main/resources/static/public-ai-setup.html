🌐 Connecting Public AI Environments

Connect Claude, ChatGPT, and Gemini to your Enterfind instance

How to connect Enterfind to the major hosted AI assistants — Claude, ChatGPT, and Gemini — so they can search and retrieve documents from your instance.

📡 Remote Access required: All three connect over the public internet, so each requires Remote Access enabled on your Enterfind instance (see the Remote Access section of Settings). Your Server ID and full remote URL are shown there. A local or LAN address will not work with any of these — the assistant runs in the cloud and must reach your instance through its remote URL.
🔐 About authentication: Enterfind's authentication is part of the GraphQL protocol itself, not a separate HTTP login. In practice this means the assistant discovers, by inspecting Enterfind, whether an instance needs credentials — and if it does, it asks you for your API key in the conversation and uses it for the rest of the session. Public demo instances need nothing; a private instance prompts you when it first needs access. There is no key to configure inside the assistant's settings.

Connecting Claude

Claude connects to Enterfind through its custom connector support, using Enterfind's remote MCP endpoint. This is the simplest of the three: you add one URL.

Requirements: a Claude plan that supports custom connectors, and Remote Access enabled on your Enterfind instance.

Your Enterfind connection URL

With Remote Access enabled, your MCP endpoint is:

https://remote-<stage>.enterfind.com/<serverId>/mcp

Your Server ID and remote URL are on the Settings page under Remote Access.

Steps

  1. In Claude, open the connectors settings and choose to add a custom connector.
  2. Paste your /mcp URL as the connector URL and save.
  3. Claude introspects the endpoint and its Enterfind tools become available in your conversations.

That's the whole setup. If the instance requires authentication, Claude will ask you for your API key when it first needs access (see the note above).

Connecting ChatGPT

ChatGPT connects to Enterfind as a Custom GPT Action. You give the GPT the URL of your instance's OpenAPI description, and ChatGPT learns how to call Enterfind's single GraphQL endpoint from that. Nothing is installed, and no code runs on your side — Enterfind already serves the description your GPT needs.

Requirements: a ChatGPT plan that can create Custom GPTs (Plus, Pro, Team, or Enterprise), and Remote Access enabled on your Enterfind instance. ChatGPT reaches Enterfind over the public internet, so the instance must be accessible through its remote URL — a local or LAN address will not work.

Your Enterfind connection URL

With Remote Access enabled, your instance publishes an OpenAPI description at:

https://remote-<stage>.enterfind.com/<serverId>/openapi.json

Your Server ID and full remote URL are shown on the Settings page under Remote Access. You can open the /openapi.json URL in a browser to confirm it returns a JSON document before pasting it into ChatGPT.

Steps

  1. In ChatGPT, create a new GPT (Explore GPTs → Create, then open the Configure tab).
  2. Under Actions, add a new action and import your /openapi.json URL as the schema. ChatGPT fetches the description and lists a single operation, executeGraphQL.
  3. Leave authentication set to None. Enterfind's own auth is handled inside the request, not at this layer (see the note above).
  4. Save the GPT. Optionally give it a name like "Enterfind" and a short instruction such as "Use the Enterfind action to search and retrieve my documents."

That's the whole setup. The GPT can now search your corpus, pull document metadata, and fetch content, all through the one action.

If it doesn't work

  • The GPT answers from memory instead of searching. Tell it explicitly to use the Enterfind action, e.g. "Search Enterfind for…". ChatGPT is less eager than some assistants to reach for a tool; a direct instruction fixes most cases.
  • Import fails or returns nothing. Open the /openapi.json URL in a browser. If it doesn't load there, the instance isn't reachable from the public internet — check that Remote Access is enabled and healthy.
  • "Not authorized" or empty results on a private instance. The GPT needs your API key; ask it to authenticate, and provide the key when prompted.

Connecting Gemini

Gemini connects to Enterfind only through the Gemini CLI — the command-line tool — using Enterfind's remote MCP endpoint. The hosted Gemini apps (Gemini web, Gemini in Google Workspace) do not currently consume MCP servers, so there is no equivalent to Claude's connector or ChatGPT's Action there; the CLI is the path.

Requirements: the Gemini CLI installed, and Remote Access enabled on your Enterfind instance.

Your Enterfind connection URL

This is the same MCP endpoint Claude uses:

https://remote-<stage>.enterfind.com/<serverId>/mcp

Your Server ID and remote URL are on the Settings page under Remote Access.

Steps

The simplest way is to just ask the CLI to do it. Start the Gemini CLI and tell it, in plain language, to add an MCP server — give it a name like enterfind and your /mcp URL:

Add an MCP server named enterfind at https://remote-<stage>.enterfind.com/<serverId>/mcp

Gemini writes the entry to its settings.json and connects to it — no restart needed. Run /mcp to confirm Enterfind shows as connected and its tools are listed.

If you prefer to configure it by hand, Gemini CLI reads its MCP servers from ~/.gemini/settings.json (applies everywhere) or a project-local .gemini/settings.json. Add Enterfind under the mcpServers block, using the httpUrl field for the remote endpoint:

{
  "mcpServers": {
    "enterfind": {
      "httpUrl": "https://remote-<stage>.enterfind.com/<serverId>/mcp"
    }
  }
}

If the instance requires authentication, Gemini asks for your API key when it first needs access, the same as the other assistants (see the note at the top). There is no key to place in settings.json.

If it doesn't work

  • Enterfind shows as disconnected. Run /mcp to see the error. Check the URL for typos and confirm the instance is reachable — open the /mcp URL host in a browser or curl it.
  • You edited settings.json by hand and nothing changed. Restart the CLI; it reads a hand-edited file only at startup. (Servers added by asking Gemini connect immediately, without a restart.)
The assistants' own menus and navigation change over time, so exact labels and click paths may differ from what you see. Everything on the Enterfind side — the connection URLs, the operation name, and the authentication behavior — is stable.
